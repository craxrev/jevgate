Claude Code plugin

jevgate

A small plugin that asks Jev, a fast yes/no model, the routine questions Claude Code would otherwise spend seconds on. Four features, each with its own switch.

What Jev is

Jev is a model from TypeSafe AI. It does not write text. You give it some context and a question like "is this command harmless?" and it answers with a probability, in about a third of a second. jevgate uses it as a quick judge, never as the thing that does the work.

Where it sits

Every time Claude Code wants to run a shell command in auto mode, this happens in order:

1
jevgate looks at the command
Harmless and sure? It says "allow". Otherwise it says nothing.
2
Your permission rules
Deny and ask rules always win, even after jevgate said allow.
3
Free pass for reads and in-repo edits
Never checked by anyone.
4
The classifier
A separate Sonnet model reviews everything left over. This is the slow step. A jevgate allow skips it.

The four features

Bash fast-lane

before a shell command runs
Question
Is this read-only, or a normal test, build, lint or typecheck?
If yes
At 95% or more, the command runs without the classifier. Roughly one second instead of several.
If unsure
Nothing changes. The classifier runs as usual.
Never asked
git push, rm, curl, installs, redirects, anything touching credentials. These always take the normal path.

Done-check

when Claude is about to say "done"
Question
Does the diff cover what you asked? Does the final message claim anything the diff does not show? Any debug prints or TODOs left in?
If a problem
Claude is told the reason and keeps working. At most twice per turn, then it is let through.
Skipped when
There is no diff, or Claude is asking you a question.

Subagent gate

before Claude spawns a subagent
Question
Is the answer already in the last few messages?
If yes
At 95% or more, the spawn is refused and Claude answers from what it has. Saves a 30 second to 2 minute detour.
If unsure
The subagent runs.

Verbatim compaction

when context gets full
Instead of
Rewriting your history into a summary, which loses paths, errors and details.
It does
Keeps every message word for word and shortens old tool outputs to their first 300 characters plus a note. Nothing is ever deleted outright. Edits and writes are always kept whole.
Jev's job
Pick up to 5 old outputs that are still needed and restore them in full.
When
At 60% context, or on /compact. With nothing to shorten, the conversation is left as is. Only Claude Code's own near-full auto-compact falls back to the summary.

After a compaction, a pane opens listing each shortened output, with a star on the ones Jev restored. Esc closes it.

Good to know

Fails quiet

If Jev is down or slow, every feature does nothing and Claude Code behaves exactly as before.

Each switch is separate

Turn any feature off in the plugin config. None depends on another.

Everything is logged

Every decision with its scores goes to decisions.jsonl in the plugin data folder. Tune thresholds from there.

What leaves your machine

Command text, the diff, recent messages, and the first 300 characters of old tool outputs go to TypeSafe. Never full outputs during compaction.

Jev can be confidently wrong

That is why the thresholds are high, the never-asked list is long, and your own rules always win.

Early access

Compaction and the UI use Claude Code function hooks, still early access. Regenerate types with /plugin-types after upgrades.
