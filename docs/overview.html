Claude Code plugin

jevgate

A small plugin that asks Jev, a fast yes/no model, the questions Claude Code would otherwise spend seconds on or skip entirely. It guards shell commands when permissions are off, and trims waits elsewhere. Four features, each with its own switch.

What Jev is

Jev is a model from TypeSafe AI. It does not write text. You give it some context and a question like "is this command harmless?" and it answers with a probability, in about a third of a second. jevgate uses it as a quick judge, never as the thing that does the work.

Where it sits

In bypass mode Claude Code runs every shell command without asking anyone. With jevgate, this happens first:

1
Free set
Read-only commands from Claude Code's own list (git status, ls, grep, cat…) run at once. About a quarter of all calls. Nothing is sent anywhere.
2
jevgate asks Jev
The command as written, plus the repo root, remotes, uncommitted changes and your last few messages. Eight harm questions, one call.
3
Over a threshold? Denied.
Claude sees the category and score, and finds another way or asks you. Otherwise the command runs.
4
Jev unreachable? Denied too.
Nothing runs unjudged. Switch to auto mode while Jev is down; free commands keep working.

A hook deny is honored in every mode, so the same guard is a hard floor under auto mode as well.

The four features

Bash guard

before a shell command runs
Questions
Would this throw away uncommitted work? Delete outside the repo? Rewrite shared history? Deploy or publish? Send data out? Read secrets? Change the system? Do something you did not ask for?
If yes
Over the category's threshold (50–70%), the command is refused with the reason. Safe commands score under 30%, harmful ones over 80%.
If no
The command runs. About half a second.
Never asked
Claude Code's own read-only set runs free, except paths that hold secrets. Editing a file with a script counts as editing, not destroying.

Done-check

when Claude is about to say "done"
Question
Does the diff cover what you asked? Does the final message claim anything the diff does not show? Any debug prints or TODOs left in?
If a problem
Claude is told the reason and keeps working. At most twice per turn, then it is let through.
Skipped when
There is no diff, or Claude is asking you a question.

Subagent gate

before Claude spawns a subagent
Question
Is the answer already in the last few messages?
If yes
At 95% or more, the spawn is refused and Claude answers from what it has. Saves a 30 second to 2 minute detour.
If unsure
The subagent runs.

Verbatim compaction

when context gets full
Instead of
Rewriting your history into a summary, which loses paths, errors and details.
It does
Keeps every message word for word and shortens old tool outputs to their first 300 characters plus a note. Nothing is ever deleted outright. Edits and writes are always kept whole.
Jev's job
Pick up to 5 old outputs that are still needed and restore them in full.
When
At 60% context, or on /compact. With nothing to shorten, the conversation is left as is. Only Claude Code's own near-full auto-compact falls back to the summary.

/jevgate prints the same tally for the session and all-time, with denials by category and the average Jev latency.

After a compaction, a pane opens listing each shortened output, with a star on the ones Jev restored. Esc closes it.

Good to know

The guard fails closed, the rest fail quiet

If Jev is down or slow, shell commands outside the free set are refused until it answers again; every other feature does nothing and Claude Code behaves as before.

Each switch is separate

Turn any feature off in the plugin config. None depends on another.

Everything is logged

Every decision with its scores goes to decisions.jsonl in the plugin data folder. Tune thresholds from there.

What leaves your machine

Command text, the diff, recent messages, and the first 300 characters of old tool outputs go to TypeSafe. Never full outputs during compaction.

Jev can be confidently wrong

That is why each category has its own threshold, tuned on real sessions, and why a refusal tells Claude the reason so it can take another route or ask you. Uploads to your own server are the known blind spot: Jev cannot tell your host from a stranger's.

Early access

Compaction and the UI use Claude Code function hooks, still early access. Regenerate types with /plugin-types after upgrades.
